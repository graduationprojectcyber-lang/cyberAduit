# دليل CyberAudit Monitor (باللهجة العراقية)

## ١. شنو اللي انبنى؟

برنامج ويب يشتغل على جهازك (Flask + SQLite)، يسجّل كل عملية أمنية تصير بالنظام:
تسجيل دخول، خروج، ملفات، صلاحيات، إدارة مستخدمين. كل حدث ينكتب بسجل تدقيق
**ما ينمسح ولا ينعدّل**، وبعدين محرّك كشف يفحص الحدث ويطلّع **تنبيه** إذا شاف نمط مشبوه.

الصفحات الموجودة:
- **المقدمة السينمائية**: شعار يترسم وخطوات تشغيل تنتظر رد السيرفر الحقيقي.
- **لوحة التحكم (Overview)**: أرقام حقيقية من قاعدة البيانات، مخطط الأحداث، توزيع الأنواع، خريطة شبكة تفاعلية، صحة النظام، وبث مباشر للأحداث.
- **سجل التدقيق (Audit logs)**: بحث وفلترة وترتيب وصفحات، وتفاصيل كاملة لكل حدث.
- **مركز التنبيهات + مساحة التحقيق**: سبب التنبيه، القاعدة، الحد، النافذة الزمنية، الخط الزمني، الأدلة، الملاحظات، الإقرار والإغلاق.
- **قواعد الكشف (Detection rules)**: خمس قواعد يگدر الأدمن يشغّلها أو يطفيها ويغيّر حدودها.
- **محاكي الأحداث (Event simulator)**: ١٠ سيناريوهات جاهزة + سيناريو موجّه من ٧ خطوات.
- **إدارة المستخدمين**، **التقارير** (CSV + تقرير للطباعة/PDF)، و**وضع العرض (Presentation mode)**.

## ٢. شلون تشغّله على ويندوز؟

١. نزّل Python 3.10 أو أحدث من python.org، وأثناء التنصيب أشّر على **Add python.exe to PATH**.
٢. افتح فولدر المشروع واضغط دبل كلك على **start.bat**.
   أول مرة يسوي بيئة `.venv` وينصّب Flask (يحتاج إنترنت بس هالمرة)، ويبني قاعدة بيانات تجريبية، ويفتح المتصفح.
٣. إذا ما انفتح، روح بنفسك على: `http://127.0.0.1:5000`

قبل المناقشة بدقائق سوّ قاعدة بيانات جديدة نظيفة:
```
.venv\Scripts\python.exe run.py --reset-db
```
وللاختبارات:
```
.venv\Scripts\python.exe -m pytest -q
```

## ٣. شلون تسجّل دخول؟

| المستخدم | كلمة السر | الدور |
|---|---|---|
| `admin` | `Admin@12345` | مدير — يگدر يسوي كلشي |
| `s.karim` | `Analyst@12345` | محلل أمني — محاكاة، تنبيهات، تصدير |
| `m.ali` | `Viewer@12345` | مشاهد — بس يشوف |

كل محاولة دخول، حتى الغلط، تنكتب بالسجل.

## ٤. شلون تشغّل سيناريوهات العرض؟

- **فشل دخول واحد**: Event simulator ← اختار **Failed login** ← **Execute simulation**.
  راح تشوف `201 Created` ورقم الحدث، والقاعدة R-01 تگول "1 of 5".
- **فشل دخول متكرر**: اختار **Multiple failed logins** (٥ محاولات) ← يطلع تنبيه جديد `ALR-xxxx`.
- **السيناريو الموجّه**: بنفس الصفحة فوق، اختار الحساب واضغط **Run scenario**.
  الخطوات السبعة تصير خضرة وحدة ورا وحدة، بس بعد ما يرد السيرفر، وبالأخير زر **Open investigation**.
- **حسابات متعددة من IP واحد**: **Multiple accounts targeted** ← قاعدة R-02.
- **حذف كثير**: **Suspicious destructive activity** ← قاعدة R-04 (ما ينحذف أي ملف حقيقي).
- **تغيير صلاحية**: **Privilege change** ← قاعدة R-05.
- **من الحقيقي مو محاكاة**: اطلع (Sign out) وجرّب تدخل بـ `a.hassan` بكلمة سر غلط ٥ مرات،
  وبعدين ادخل كأدمن ← راح تلگى تنبيه R-01 حقيقي.

## ٥. شلون يشتغل محرّك الكشف؟

كل ما ينكتب حدث، المحرّك:
١. يشوف أي قاعدة تنطبق عليه (مثلاً فشل دخول ← R-01 و R-02).
٢. يحسب الأحداث المطابقة بالنافذة الزمنية (استعلام SQL بمعاملات).
٣. يقارن العدد بالحد (threshold).
٤. إذا وصل الحد: يفتح تنبيه جديد، أو يضيف الدليل للتنبيه المفتوح إذا كان موجود.
٥. حتى إنشاء التنبيه نفسه ينكتب بالسجل (`alert.created`).

| القاعدة | متى تشتغل |
|---|---|
| R-01 | ٥ محاولات دخول فاشلة لنفس الحساب خلال ١٠ دقائق |
| R-02 | ٣ حسابات مختلفة فشلت من نفس الـ IP خلال ١٥ دقيقة |
| R-03 | ٤ عمليات مرفوضة لنفس الحساب خلال ٣٠ دقيقة |
| R-04 | ١٠ عمليات حذف لنفس الحساب خلال ٥ دقائق |
| R-05 | أي تغيير بالأدوار أو الصلاحيات |

ماكو ذكاء اصطناعي ولا Machine Learning، كله قواعد واضحة وتگدر تشرحها.
والتنبيه معناه "نشاط مشبوه يحتاج تحقيق"، **مو إثبات** إنو صار هجوم.

## ٦. شلون تشتغل قاعدة البيانات والسجلات؟

- الملف: `instance/cyberaudit.db` (SQLite).
- الجداول: `users`، `audit_events`، `rules`، `alerts`، `alert_events` (الأدلة)، `alert_notes`.
- جدول `audit_events` عليه **Triggers** ترفض أي `UPDATE` أو `DELETE`، يعني السجل إضافة فقط.
- كل سجل بيه **hash** (SHA-256) لمحتواه + hash السجل اللي قبله، فإذا أحد عدّل أو حذف سجل
  تنكسر السلسلة. زر **Verify integrity** بالشريط الجانبي (للأدمن) يعيد حساب كل السلسلة.
- كلمات السر تنحفظ hash بس، وما تنكتب أبد بالسجل ولا تطلع للمتصفح.
- **حدود صادقة**: هذا كشف للتلاعب محلياً، مو حماية مطلقة؛ واحد عنده وصول مباشر للملف يگدر يعيد بناء السلسلة كلها.

## ٧. شنو المحاكى وشنو الحقيقي؟

**حقيقي ١٠٠٪**: تسجيل الدخول والجلسات، CSRF، الصلاحيات، تشفير كلمات السر، كتابة السجل،
سلسلة الـ hash، محرّك الكشف، التنبيهات والتحقيق، البحث والفلترة، التقارير والتصدير، صحة النظام.

**محاكى/تجريبي**:
- المستخدمين والـ ~١٨٥٠ حدث الأولية بيانات وهمية (شارة **Demo seed**).
- أحداث المحاكي (شارة **Simulated**) تمر بنفس المسار الحقيقي وتنحفظ بالقاعدة، بس ما تلمس ملفات ولا شبكة.
- عناوين الـ IP عناوين داخلية/تجريبية، مو مواقع جغرافية.
- أي عملية حقيقية تسويها انت بالبرنامج (دخول، تغيير مستخدم...) تطلع بشارة **Live**.

## ٨. شلون تعرض المشروع للمشرف بثقة؟

- قبل المناقشة: `run.py --reset-db`، افتح المتصفح بملء الشاشة (F11)، وادخل كـ `admin`.
- ابدأ من **Presentation mode** واتبع الخطوات الثمانية بالترتيب (الأسهم ← → تنقلك).
- كل رقم تشوفه گول: "هذا جاي من استعلام على قاعدة البيانات"، وورّيهم شارات Demo/Simulated/Live.
- بالتنبيه ركّز على: القاعدة، الحد، النافذة الزمنية، والحدث اللي سبب التنبيه (Trigger event).
- اذا سألوك "شلون تضمن السجل ما يتغير؟" ورّيهم Verify integrity واشرح الـ triggers والـ hash chain، واذكر الحدود بصراحة.
- اذا سألوك عن الأمان: CSRF، تشفير كلمات السر، الصلاحيات بالسيرفر، SQL بمعاملات، CSP، وحماية آخر أدمن.
- اذا صار خطأ أو السيرفر طفى، الواجهة تگول "Backend unavailable" بصراحة وما تزوّر نجاح — هاي بحد ذاتها نقطة قوة.
- النص الكامل للعرض موجود بـ `docs/PRESENTATION_SCRIPT.md`.
