# نص العرض — CyberAudit Monitor (حوالي ١٠ دقائق)

**التحضير (قبل ٥ دقائق):**
- شغّل `start.bat` أو `run.py --reset-db` حتى تبدي ببيانات نظيفة.
- ادخل بـ `admin` / `Admin@12345`، كبّر المتصفح (F11).
- افتح **Presentation mode** من الشريط الجانبي.

---

### ١. مقدمة النظام (دقيقة)
**اضغط:** Replay intro.
**گول:** "هذا CyberAudit Monitor، نظام تدقيق ومراقبة أمنية. كل خطوة بالتشغيل تنتظر رد حقيقي من السيرفر:
قاعدة البيانات، القواعد، وبث الأحداث. إذا السيرفر ما رد، الخطوة تطلع حمرة، ما نزوّر."

### ٢. لوحة التحكم (دقيقة ونص)
**ورّي:** البطاقات الست، مخطط الأحداث (بدّل 24 h / 7 days)، التوزيع، خريطة الشبكة (اضغط على 10.0.4.23).
**گول:** "كل رقم استعلام على SQLite. شارة Demo data تبيّن إن النشاط تجريبي، والـ IP عناوين داخلية مو مواقع جغرافية.
لوحة System health فحوصات حقيقية للسيرفر وقاعدة البيانات."

### ٣. فشل دخول واحد (دقيقة)
**ارجع لـ Presentation mode ← اضغط:** Failed login.
**گول:** "انكتب حدث واحد بالقاعدة، والقاعدة R-01 حسبته: 1 من 5. ما طلع تنبيه لأن الحد ما وصل."
**ورّي:** السطر الجديد بالبث المباشر.

### ٤. فشل دخول متكرر (دقيقة)
**اضغط:** Repeated failed logins (أو بالمحاكي Run scenario للسيناريو الموجّه).
**گول:** "خمس محاولات فاشلة لنفس الحساب خلال ١٠ دقايق، وصلنا الحد، فالمحرّك فتح تنبيه.
بالسيناريو الموجّه كل خطوة تخضر بس بعد ما السيرفر يأكد."

### ٥. التنبيه الناتج (دقيقة)
**اضغط:** Open investigation (أو Alerts).
**گول:** "التنبيه يشرح ليش طلع: القاعدة R-01، الحد ٥، النافذة ١٠ دقايق، وعدد الأدلة.
الصياغة 'Repeated authentication failures detected' و'requires investigation'، لأن النمط مو إثبات هجوم."

### ٦. مساحة التحقيق (دقيقتين)
**ورّي:** الخط الزمني (قبل، الأدلة، Trigger event، بعد)، Related entities، الاستنتاج التلقائي
("ماكو دخول ناجح من نفس الـ IP بعد الفشل")، الخطوات المقترحة.
**اضغط:** Acknowledge ← أضف ملاحظة ← Resolve واكتب ملخص.
**گول:** "حتى أفعال المحلل نفسها تنكتب بالسجل، وتطلع هنا بالخط الزمني."
**اختياري:** View raw trigger event.

### ٧. فلترة السجلات (دقيقة)
**روح:** Audit logs ← Action = Login، Outcome = Failed ← Apply filters ← افتح حدث ← Copy ID.
**گول:** "البحث والفلترة والترتيب بالسيرفر وبـ SQL بمعاملات، فحقن SQL ما يشتغل.
وبالتفاصيل تشوف الوقت UTC والمحلي، والـ hash، وكلمات السر عمرها ما تنحفظ."

### ٨. التقرير (دقيقة)
**روح:** Reports ← Last 7 days ← Export CSV ← Printable report ← Print / Save as PDF.
**گول:** "التقرير من استعلام مباشر، بيه وقت الإنشاء والفلاتر. الـ CSV محمي من حقن المعادلات،
والتصدير نفسه ينكتب بالسجل، ومسموح بس للمحلل والأدمن."

### ختام (نص دقيقة)
**اضغط (للأدمن):** Verify integrity بالشريط الجانبي.
**گول:** "السجل إضافة فقط بالـ triggers ومربوط بسلسلة SHA-256، فأي تعديل ينكشف.
هذا كشف تلاعب محلي، مو ضمان مطلق، والتطوير الجاي ممكن يكون توقيع دوري للـ hash خارج الجهاز."

---

### أسئلة متوقعة
- **شلون تمنع الوصول غير المصرّح؟** الصلاحيات تنفحص بالسيرفر لكل طلب، والمحاولة المرفوضة تنكتب (`access.denied`)؛ جرّبها بحساب `m.ali`.
- **ليش ماكو قفل للحساب؟** النظام مصمم للكشف والتحقيق؛ القفل ممكن ينضاف، بس هسه التنبيه هو الاستجابة.
- **هل البيانات حقيقية؟** المستخدمين والأحداث الأولية وهمية ومعلّمة، بس المسار (تسجيل، كشف، تنبيه) حقيقي ١٠٠٪، وأي دخول حقيقي تسويه يطلع **Live**.
- **شنو التقنيات؟** Python 3 و Flask و SQLite و HTML/CSS/JavaScript بدون مكتبات خارجية بالواجهة (المخططات SVG مكتوبة يدوياً، وتشتغل بدون إنترنت).
